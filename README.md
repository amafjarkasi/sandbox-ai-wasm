# SandboxAI

> Secure AI code execution platform powered by [Edge.js](https://edgejs.org) WASM sandboxing

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](https://opensource.org/licenses/MIT)
[![Edge.js](https://img.shields.io/badge/Powered%20by-Edge.js-orange)](https://edgejs.org)

**Run untrusted AI-generated code with sub-5ms cold starts.**

## Why SandboxAI?

The AI agent ecosystem has a critical problem: how do you safely execute code generated by LLMs? Current solutions rely on Docker containers with 300ms+ cold starts, making them unsuitable for real-time AI applications.

SandboxAI leverages Edge.js's `--safe` mode to run code inside a WebAssembly sandbox with **<5ms startup** — 60x faster than containers, with full Node.js API compatibility.

| Approach | Cold Start | Security | Node.js Compat |
|----------|-----------|----------|-----------------|
| Docker | >300ms | Container isolation | Full |
| VM | >1s | VM isolation | Full |
| Browser sandbox | <5ms | Same-origin only | Limited |
| **SandboxAI (Edge.js)** | **<5ms** | **WASM sandbox** | **Full** |

## Features

- **WASM Sandboxing** — Edge.js `--safe` mode runs code in a fully isolated WebAssembly sandbox
- **Sub-5ms Cold Starts** — 60x faster than containers
- **Multi-Engine Support** — Switch between V8, JavaScriptCore, QuickJS, SpiderMonkey, or Hermes
- **AI Agent Ready** — MCP-compatible tool interface for LLM agents
- **Real-time Dashboard** — Monitor executions, resource usage, and results
- **Streaming Output** — Server-Sent Events for live execution feedback
- **Policy Engine** — Fine-grained resource limits, network policies, and API allowlists
- **Security Analysis** — Detect dangerous code patterns before execution
- **Audit Logging** — Complete chain of custody for all executions
- **Rate Limiting** — Built-in request throttling per client
- **100% Node.js Compatible** — Every npm package works out of the box

## Quick Start

```bash
# Install Edge.js
curl -fsSL https://edgejs.org/install | bash

# Clone and run
git clone https://github.com/yourusername/sandboxai.git
cd sandboxai

# Install dependencies
npm install

# Start the server (normal mode)
edge server.js

# Start with WASM sandboxing (safe mode)
edge --safe server.js

# With API key authentication
API_KEY=your-secret-key edge server.js
```

## Configuration

Environment variables for security and performance tuning:

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3000` | HTTP server port |
| `HOST` | `0.0.0.0` | Bind address |
| `API_KEY` | - | Enable API key authentication |
| `CORS_ORIGINS` | `*` | Comma-separated allowed origins |
| `MAX_BODY_SIZE` | `1048576` | Max request body size (bytes) |
| `MAX_CONCURRENCY` | `10` | Max concurrent executions |
| `DEFAULT_TIMEOUT` | `30000` | Default execution timeout (ms) |
| `REQUEST_TIMEOUT_MS` | `30000` | HTTP request timeout (ms) |
| `RATE_LIMIT_WINDOW_MS` | `60000` | Rate limit window (ms) |
| `RATE_LIMIT_MAX_REQUESTS` | `100` | Max requests per window |

## API Reference

### Execute Code

```bash
# Execute JavaScript in a sandbox
curl -X POST http://localhost:3000/api/execute \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{
    "code": "const result = [1,2,3].map(x => x * 2); console.log(result);",
    "engine": "v8",
    "timeout": 5000,
    "memory": "64mb"
  }'
```

Response:
```json
{
  "id": "exec_abc123",
  "status": "completed",
  "output": "[ 2, 4, 6 ]\n",
  "durationMs": 3,
  "memoryUsedMb": 12.4,
  "engine": "v8"
}
```

### Stream Execution (SSE)

```bash
curl -N http://localhost:3000/api/execute/stream \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{"code": "for(let i=0;i<5;i++){console.log(i);await new Promise(r=>setTimeout(r,500))}"}'
```

### AI Agent (MCP)

```bash
# MCP-compatible tool endpoint for AI agents
curl -X POST http://localhost:3000/mcp/tools/execute \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{
    "code": "fetch('https://api.example.com/data').then(r=>r.json())",
    "context": "Data retrieval for analysis"
  }'
```

### Engine Selection

```bash

```

## Security Features

### Security Policies

Define fine-grained execution policies:

```javascript
const policy = {
  timeout: 5000,           // 5s max execution time
  memory: "64mb",          // 64MB memory limit
  network: "none",         // No network access
  filesystem: "readonly",  // Read-only filesystem
  modules: ["node:crypto", "node:buffer"],  // Allowed modules
  env: {},                 // No env vars
  maxOutputSize: "1mb"    // Max stdout/stderr size
};
```

### Dangerous Code Detection

The policy engine analyzes code for dangerous patterns:

```bash
# Analyze code before execution
curl -X POST http://localhost:3000/api/analyze \
  -H "Content-Type: application/json" \
  -d '{"code": "require('child_process').exec('rm -rf /')"}'
```

Response:
```json
{
  "analysis": {
    "isDangerous": true,
    "findings": [
      {
        "category": "command_execution",
        "severity": "critical",
        "description": "Detected child_process execution"
      }
    ]
  }
}
```

## Security Hardening

### Production Checklist

1. **Enable API Key Authentication**
   ```bash
   API_KEY=$(openssl rand -hex 32) edge --safe server.js
   ```

2. **Configure CORS**
   ```bash
   CORS_ORIGINS=https://yourdomain.com edge server.js
   ```

3. **Set Rate Limits**
   ```bash
   RATE_LIMIT_MAX_REQUESTS=50 RATE_LIMIT_WINDOW_MS=60000 edge server.js
   ```

4. **Use WASM Safe Mode**
   ```bash
   edge --safe server.js
   ```

5. **Limit Body Size**
   ```bash
   MAX_BODY_SIZE=524288 edge server.js  # 512KB limit
   ```

### Security Patterns Detected

The policy engine detects 11 categories of dangerous patterns:

| Category | Severity | Examples |
|----------|----------|----------|
| Command Execution | Critical | `child_process`, `exec`, `spawn` |
| File System | Critical | `fs.writeFile`, `fs.unlink` |
| Network | High | `http.request`, `fetch` to internal IPs |
| Code Injection | Critical | `eval`, `new Function`, `vm.runInContext` |
| Prototype Pollution | High | `__proto__`, `constructor` manipulation |
| Regex DoS | Medium | ReDoS vulnerable patterns |
| Global This | Medium | `globalThis` access |
| Import/Require | High | Dynamic imports, require statements |
| Process | Critical | `process.exit`, `process.kill` |
| Worker Threads | High | `Worker`, `worker_threads` |
| WASM | High | `WebAssembly.instantiate` with buffers |
